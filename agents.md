# AGENTS.md

This file governs how AI agents interact with the `paper2code` repository.
All agents — regardless of the model or orchestration framework — **must read
and follow this file before performing any task**.

---

## 1. Repository Purpose

`paper2code` translates peer-reviewed academic papers (algorithms, data
structures, protocols) into tested, production-quality code using AI agents.
Every implementation must be **directly traceable** to its source paper.
Agents must never invent behaviour that is not described in the paper.

---

## 2. Repository Layout

```
paper2code/
├── AGENTS.md                  ← you are here; read before anything else
├── README.md
├── disclaimer/
│   └── AI_Generated_Disclaimer.md
├── implementations/
│   └── <paper-slug>/          ← one directory per paper
│       ├── paper.md           ← metadata (see §4)
│       ├── prompt.md          ← the prompt used to generate this impl (see §5)
│       ├── <package>.go       ← implementation
│       ├── <package>_test.go  ← tests
│       └── go.mod
└── scripts/
    └── validate.sh            ← runs `go test -race ./...` on all packages
```

Agents **must not** create files outside this structure without explicit
instruction.

## 3. Coding Standards

### Language
All implementations in this repository are **Go**. Use the latest stable
Go version declared in the relevant `go.mod`.

### Idioms
| Concern | Rule |
|---|---|
| Shared pointer fields | `unsafe.Pointer` + `sync/atomic` CAS — never raw pointer assignment |
| Shared integer/bool fields | `sync/atomic` load/store/CAS on `int32` or `int64` |
| Locks | Only if the paper explicitly uses locks; justify with a comment |
| Error handling | Return typed errors or sentinel `OpResult` constants; never `panic` in library code |
| Naming | Mirror the paper's names for types, functions, and variables; add idiomatic Go casing |
| Package name | Lowercase, no underscores, derived from the paper slug |

### Comments — mandatory format
Every non-trivial function **must** carry a traceability comment:

```go
// Paper: Fig. 4, lines 96–111.
func (l *List) help(I *Info) bool { … }
```

Use `// NOTE:` for any deviation from the pseudocode, and `// ASSUME:` for
any detail the paper leaves unspecified (e.g. memory reclamation strategy).

## 4. Paper Metadata File (`paper.md`)

Each implementation directory must contain a `paper.md` with this exact
structure:

```markdown
# Paper Metadata

- **Title:**   <full paper title>
- **Authors:** <comma-separated author names>
- **Venue:**   <conference or journal name and year>
- **DOI:**     <doi url>
- **PDF:**     <direct pdf url>
- **Licence:** <paper licence, e.g. CC-BY 4.0>

## Abstract
<copy the abstract verbatim>

## Implemented Sections
- Section 3 — Sequential Specification
- Section 4 — Non-blocking Implementation (Fig. 2, 3, 4)

## Known Omissions
- <list any parts of the paper not implemented and why>
```

## 6. Test Requirements

Agents must produce a `_test.go` file that satisfies **all** of the
following before considering a task complete:

- [ ] `go test ./...` passes with exit code 0
- [ ] `go test -race ./...` passes with exit code 0 (no data races)
- [ ] Sequential correctness tests cover every public operation
- [ ] Boundary conditions are tested (empty structure, single element,
      at-limit operations)
- [ ] At least one concurrent stress test using `sync.WaitGroup` with
      ≥ 4 goroutines
- [ ] At least one `Example` function demonstrating primary usage

Agents must run the tests themselves and fix any failures before
delivering output. Do not report success without actually executing
`go test -race ./...`.

## 7. Disclaimer

Every implementation directory inherits the repository-level disclaimer
(`disclaimer/AI_Generated_Disclaimer.md`). Agents must not remove,
modify, or contradict this disclaimer.

Additionally, the package-level doc comment in `<package>.go` must open
with:

```go
// Package <name> is an AI-generated implementation of:
//
//   <Paper title>
//   <Authors>, <Venue>.
//   <DOI>
//
// Generated by <model> on <date>. See AGENTS.md and the repository
// disclaimer before using in production.
```

---

## 8. What Agents Must NOT Do

- **Invent behaviour.** If the paper does not describe it, do not implement
  it. Use `// ASSUME:` to document any gap you must fill to make the code
  compile.
- **Silently deviate.** Every deviation from the paper's pseudocode must be
  marked `// NOTE: deviation — <reason>`.
- **Remove tests.** Agents must not delete existing tests to make the suite
  pass.
- **Modify other packages.** An agent working on `implementations/foo/` must
  not touch files in `implementations/bar/` or any other directory.
- **Commit secrets or credentials.** No API keys, tokens, or passwords.
- **Rewrite `AGENTS.md`.** This file may only be changed by a human via a
  pull request.

---

## 9. Pull Request Checklist

Before opening a PR, an agent must self-verify and include this checklist
in the PR description:

```
- [ ] paper.md present and fully filled in
- [ ] prompt.md present with verbatim prompt and model name
- [ ] Package doc comment contains AI-generation notice
- [ ] All functions have // Paper: Fig. N, lines X-Y comments
- [ ] All deviations marked // NOTE:
- [ ] All assumptions marked // ASSUME:
- [ ] go test ./... passes
- [ ] go test -race ./... passes
- [ ] No files modified outside implementations/<this-slug>/
```

---

## 10. Versioning

`go.mod` module paths follow the pattern:

```
module github.com/example/paper2code/implementations/<paper-slug>
```

Use the Go version that was current at the time of generation. Do not
upgrade other packages' `go.mod` files.
